# ColonizationNeeds project

This is a standalone native Windows Forms application for Elite Dangerous colonization supplies. The canonical sources are src/ColonizationNeeds.cs src/JournalCargoTracker.cs, and src/SharedInventoryClient.cs. Build with powershell -NoProfile -ExecutionPolicy Bypass -File ./build.ps1. The script builds bin/ColonizationNeeds.exe and runs the self-tests. No external packages or SDK installation are needed for the script. The csproj supports IDE editing with .NET Framework 4.8 development tools installed.

Raven reads remain read-only by default. Optional delivery reporting is explicitly enabled in Settings with the player's Raven API key. Preserve saved commander-specific inventory, Windows DPAPI key encryption, inventory Add/Remove/Set total operations, grouped commodity categories, and the dark amber palette and saved opacity. Never put credentials or runtime inventory into this repository. The executable is deliberately included because the user wants source and a ready-to-run app available across computers.

Delivery reporting captures only new ColonisationContribution events for contribution history and construction-depot snapshots for authoritative requirements. Never credit CargoDepot, ship loading, or carrier inventory edits as project deliveries. Save reporting state before acknowledging a journal event and before sending POST. Uncertain contribution outcomes require explicit review; do not automatically retry them. Keep per-commander reporting state and process locks, timestamp checks against stale depot uploads, and the mocked reporting checks in tests/Test-Reporting.ps1. Historical journal events are not uploaded automatically.

Release 1.27 uses Automatic and Manual tracking. MarketSell adds to the registered carrier; MarketBuy removes. Confirmed CargoTransfer tocarrier/toship adds/removes. Never infer deposits from ship acquisitions. Ambiguous movements require explicit review. In both tracking modes, To deliver is outstanding construction need. To collect subtracts selected Stock, Inbound and Outbound. The acquisition-based Collect/Colonize modes and duplicate Required/Still needed columns are historical. Read new construction-depot snapshots as absolute RequiredAmount minus ProvidedAmount, match by project MarketID, save per commander, and prefer newer Raven depot observation timestamps. Generic project timestamps are not depot freshness evidence. Without a newer depot observation, use the smaller known nonnegative remaining count. Do not subtract deliveries a second time or debit carrier stock on delivery. Keep bright cyan positive/unknown delivery text and green visible zero rows; To collect uses red positive shortages. Depot snapshots update delivery requirements only, not inventory acquisition accounting.

Completion reporting requires a new journal ConstructionComplete boolean true and reporting enabled. Never infer completion from zero requirements. Persist completion requests, finish or explicitly resolve final contribution credits first, check Raven before POST /project/{buildId}/complete and verify afterward. Interrupted completion checks resume safely without replaying historical completions or duplicating contribution credit.
